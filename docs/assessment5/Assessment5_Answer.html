Question: As the Lead Cloud Architect of a retail company starting a Smart Store Initiative, how would we design the system across IaaS, PaaS and SaaS? The portal must run on IaaS with JavaScript client components, the IoT sensor backend must run on PaaS, and team collaboration must use SaaS. All three must work together securely and efficiently.

1. Overview of the Solution

We decided which service model to use for each part based on how much control that part needs. The web portal needs full control of the operating system and web server, so it goes on IaaS. The IoT backend only needs our processing code, so it goes on PaaS, where the provider runs the servers, scaling and databases. The collaboration tool needs no code from us at all, so we use a SaaS product.

The three tiers do not call each other directly. They connect through one integration layer made up of an API gateway, an event bus, a single identity provider and private network links. On top of this we use our own project, GreenOps, to run flexible background work (analytics, ML training, backups) in the cloud region and hour with the cleanest electricity, without delaying anything urgent. 2. IaaS Tier: Interactive Web Portal

We chose IaaS because the portal needs things that only IaaS allows: our own Nginx configuration, a fixed Node.js version, OS hardening and custom TLS settings.

  • Compute: a group of Linux virtual machines (for example AWS EC2 or Azure VM Scale Sets) that grows and shrinks with the number of visitors. Each VM runs Nginx in front of a Node.js application. All VMs are created from one hardened image, and the network is written in Terraform so it can be rebuilt the same way in every region.
  • Network: one virtual network per region with three subnets. The public subnet has only the load balancer and the NAT gateway. The VMs sit in a private application subnet, and the cache and database sit in a private data subnet. Each subnet only accepts traffic from the layer in front of it.
  • JavaScript client: the static JavaScript and CSS files are served from a CDN. Live data such as stock levels, offers and queue length is pushed to the page over a WebSocket through the API gateway, so the page updates without reloading.
  • Security: a web application firewall at the CDN, HTTPS everywhere, no SSH open to the internet, automatic OS patching and encrypted disks.

3. PaaS Tier: Real-Time IoT Backend

Sensor data arrives very often and in bursts, for example when a store opens. We do not want to manage servers for this, so we use PaaS. The provider handles the runtime, scaling and database setup, and our developers only write the functions that process the sensor messages.

  • Device connection: beacons, temperature sensors and inventory sensors send data through an in-store gateway to a managed IoT hub (AWS IoT Core or Azure IoT Hub). Messages use MQTT over TLS, and every device has its own certificate, so one stolen device can be blocked on its own.
  • Ingestion: the hub passes messages to a managed event stream (Kinesis or Event Hubs). The stream absorbs sudden bursts and lets us replay old data.
  • Fast path: serverless functions check each message against simple rules, such as a fridge above 5 °C or a shelf running low. They save the live state in a managed NoSQL and time-series database and send alerts to the event bus. This happens within seconds.
  • Slow path: all raw data is stored in a data lake. Daily sales and footfall reports and weekly demand-forecast training run as batch jobs. These jobs are not urgent, so GreenOps schedules them (Section 6).

4. SaaS Tier: Team Collaboration

Store managers and the head office need chat, shared documents and planning straight away, without anyone running servers or writing code. We therefore use a SaaS product such as Microsoft 365 (Teams, SharePoint, Planner) or Google Workspace. The vendor runs and updates everything, and our work is limited to the following:

  • Identity: staff log in through the same identity provider as the rest of the system, using single sign-on and multi-factor authentication. Accounts are added and removed automatically from HR records, so a person who leaves loses access everywhere at once.
  • Integration: the PaaS functions post alerts to a channel such as #store-ops using a webhook, for example “Store 12, fridge 3 is at 9 °C”. Stock plans, schedules and campaign rollouts are kept in shared documents and task lists.
  • Data protection: data loss prevention rules, access only from company devices, and retention policies, all set from the vendor's admin console.

6. Efficiency Using GreenOps (Our Project)

The design already avoids waste. The VMs scale with visitor numbers, the serverless functions are billed per message, and the SaaS tier needs no servers. Our GreenOps project adds one more factor, the carbon emitted by the electricity that runs each job.

In GreenOps every job has a type, a deadline, a budget and a rule about which countries its data may be processed in. For each job the scheduler checks every allowed region and start hour. It compares their expected carbon emissions, cost and risk of missing the deadline, then chooses the best option. Figure 5 shows how this applies to the Smart Store workloads.

Figure 5: How GreenOps handles each type of Smart Store workload

Most of the slow-path work in Figure 3 is not urgent, which is where GreenOps helps. In our project tests using real 2024 electricity data, GreenOps reduced carbon emissions by 26.8% compared with round-robin scheduling and by 5.3% compared with always choosing the greenest region. Cost went up by less than 1%, almost all deadlines were met (0.09% of jobs finished late), and each decision took about 0.1 ms. Jobs whose data must stay in one country are never moved to another country; they can only be delayed to a cleaner hour.

8. Conclusion

Each part of the Smart Store system uses the service model that gives it the control it needs. IaaS is used for the web portal, because we need full control of the OS and web server. PaaS is used for the IoT backend, because the provider handles the runtime, scaling and databases. SaaS is used for team collaboration, because it is ready immediately with nothing to maintain. A shared integration layer connects the tiers securely while keeping them independent. Finally, GreenOps makes the system efficient in carbon as well as cost: urgent work runs immediately, and flexible work runs in the cleanest region and hour that still meets its deadline.
